# 소비 권장일 묶음 알림 메일

제목은 항상 **[콕집서] 냉장고 속 재료를 확인해 주세요**입니다.

한 번의 발송에서 같은 계정·수신 주소의 대상 재료를 한 통에 모읍니다. D-Day → D-1 → D-3 순서로 구역을 표시하고, 같은 구역의 재료명은 `대파 · 우유`처럼 연결합니다. 전체 개수는 구역 수가 아니라 실제 재료 수입니다. 대상이 없는 구역은 표시하지 않습니다.

본문은 콕집서/냉장고 알림 헤더, 안내 제목, 전체 대상 개수, 오늘 확인할 재료 목록, 내 냉장고 확인하기 버튼, 소비 권장일 안내와 알림 설정 링크로 구성합니다. HTML은 이메일 클라이언트 호환성을 위한 인라인 스타일·테이블 구조입니다. 이름은 HTML escape 처리하고 텍스트 본문도 함께 발송합니다.

## 구현

- `emailTemplates.ts`: 재료마다 daysLeft(0/1/3)를 받아 기한별 구역 렌더링. 기존 단일 재료 호출도 호환.
- `202611030001_email_digests.sql`: 영속 digest_id, 계정별 묶음 선점·재검사·원자적 결과 기록. 최대 25개 **계정**을 처리하므로 한 계정의 재료가 25개를 넘더라도 여러 통으로 잘리지 않음.
- `emailNotifications.ts`: 같은 digest_id의 항목을 한 번의 transport 호출로 발송. `sent`/`failed`는 메일 통수, `sentIngredients`는 포함된 재료 수.
- 발송 중단 후에도 같은 묶음 ID/중복 방지 키를 사용. 성공 기록은 묶음 전체에 원자적으로 반영. 불확실한 SMTP 발송은 재발송하지 않으며 내용 지문이 달라지면 성공으로 처리하지 않음.
- 다른 계정끼리는 묶지 않음. 본인 계정 테스트의 서버 UUID 검증·수신 동의·기한 경과 제외·발송 직전 재검사도 유지.
- 나중에 새 대상이 추가되면 그 시점의 새 미발송 묶음은 별도 1통으로 처리할 수 있음. 이미 발송한 항목은 반복 포함하지 않음.

직접 테스트 스크립트도 D-Day/D-1/D-3을 한 통으로 합칩니다. 단, 스크립트는 자동 발송 DB 기록을 남기지 않는 별도 도구이므로, 실제 자동 로직 검증에는 설정 화면의 본인 계정 테스트 버튼을 사용합니다.

## 적용/검증

2026-11-03 사용자 승인 후 현재 Supabase DB에 202611030001 적용·이력 기록, 기존 email-reminder-worker 코드 업데이트 배포 완료. 웹앱·Cron·발송 허용 설정은 변경하지 않았으며, 실제 사용자에게 메일을 보내는 테스트는 실행하지 않았습니다.

빌드 및 테스트 292개 통과. 4개 재료의 D-Day/D-1/D-3 묶음, 서로 다른 계정 분리, 32개 재료의 단일 묶음, 중단 후 묶음 ID 유지, 동의 해제 시 전체 취소, HTML 특수문자 처리와 본문 총 개수를 확인했습니다.

예시 미리보기: `dist-email/digest-preview.html` (실제 사용자 데이터가 아닌 두부·대파·우유·양배추 예시). 제목은 메일 제목 필드에 설정되며 본문의 안내 제목과 구분됩니다.
